# v1.1.0 开放指南

v1.1.0 的重点是**配音**和**画面**：每个角色有自己的声音，台词和字幕对得上，音效和配乐不再盖住人声；动态镜头不再卡顿，每个镜头可以有自己的色调和转场，角色一致性多了两道约束。制作页面也相应加了试听、整集声音样片和逐镜画面对照。

第一次安装请先按 [v1.0.0 开放指南](OPEN_GUIDE_v1.0.0.md) 第 2～3 节准备环境、安装和过开工检查，那部分流程没有变化。本指南讲 v1.1.0 新增和改变的内容。

## 1. 开放范围与验证范围

| | 内容 |
|---|---|
| **新增** | 按角色选声；可替换的配音引擎；配音去静音与响度统一；长台词逐段字幕；平滑的配乐与音效闪避；玄幻音效（冲击、剑鸣、能量、雷、火）；国风五声音阶配乐；动态镜头平滑变速；放大锐化；每镜色调与转场；动作提示词带角色外观；视频复检对照关键帧；页面上的配音表、试听、整集声音样片和逐镜画面查看 |
| **已验证** | 11 项离线结构检查、74 项不启动模型的单元测试（v1.0.0 的 47 项加 27 项配音与画面测试）；页面在演示数据上做过浏览器交互检查，包括试听、声音样片、画面对话框、手机宽度 |
| **未验证** | 完整动态出片仍未通过验收（见 [`VALIDATION.md`](VALIDATION.md)）。本版本里会影响生成结果的两处改动——动作提示词加入角色外观、视频复检加入关键帧参照——都还没有在真实模型上跑过，效果需要你在自己的机器上确认 |

测试用的配音引擎是一个输出提示音的替身程序（`tests/fake_tts.py`），不是真实语音。macOS `say` 和第 3.3 节里的其他引擎示例没有在本次发布中实际运行。

## 2. 从 v1.0.0 升级

```bash
git pull
```

```bash
python install.py /path/to/ComfyUI --apply
```

安装脚本会保留你的 `drama/production_config.json`。新增的配置项都有代码内默认值，旧配置不改也能运行，并且**自动获得**本版本的大部分新行为：按角色选声、配音去静音与响度统一、逐段字幕、平滑闪避、新音效、动态镜头变速、放大锐化、逐镜色调与转场、动作提示词带外观、视频复检对照关键帧。

只有内置配乐风格不同：旧配置里 `music.builtin.style` 是原来的值，所以仍是氛围和弦垫；仓库默认配置是 `guofeng`（国风五声音阶拨弦）。

想关掉某项新行为或换成新默认值，对照第 6 节在配置里加对应的键；也可以用 `--reset-config` 整个换成仓库默认（旧文件会备份为 `.bak-时间戳`）。改完配置都要重签证书：

```bash
python drama/workflow_build.py --certify
```

重启 ComfyUI 后打开制作页面，开工检查的“配音引擎”一项现在会核对**你的分镜实际用到的语音是否已安装**。

## 3. 配音

### 3.1 每个角色用什么声音

v1.0.0 有一个问题：从页面或画布提交的任务会把所有角色都换成画布「配音字幕与配乐」节点里的那一个声音。v1.1.0 改为按下面的顺序为每位说话人选声，画布节点的声音只作为最后的默认值：

1. 角色表里该角色的 `voice` 和 `voice_rate`
2. 配置文件 `voice.per_character` 里按角色名指定的声音
3. 角色表里的 `gender`：`male`、`female`、`elder`、`child`，对应配置里的 `_male`、`_female`、`_elder`、`_child`
4. 按名字和外观描述推断：名字含“老、爷、婆”等判为长者，含“姐、妹、仙子”等判为女性，含“哥、公子、剑修”等判为男性；外观里写了“女性 / 少女”“男性 / 少年”也会被识别
5. `_default`

长者默认语速乘 0.88。最稳妥的做法是在角色表里直接写明：

```json
"characters": {
  "少年剑修": {"anchor": "……", "gender": "male", "voice": "Reed", "voice_rate": 175},
  "白衣师姐": {"anchor": "……", "gender": "female", "voice": "Tingting", "voice_rate": 165}
}
```

`voice_rate` 是每分钟字数，范围 60～400。用 `say` 时可以只写短名（`Reed`），会自动补成新版 macOS 需要的全名。

### 3.2 先听，再出画面

分镜导入后，提交制作之前，页面的分镜预览里有两块新内容：

- **配音表**：每位说话人分到的音色、语速、选声依据（“角色表指定”“按性别”“按名字推断”等）、台词数，以及该语音在本机是否已安装。点「▶ 试听」用这位角色的第一句台词合成一遍；镜头列表里每句台词旁边也有 ▶。
- **整集声音样片**：把整集的配音、音效和配乐按正式制作的规则混成一条音轨，同时列出每个镜头的起点、**按配音调整后的实际时长**、配音长度和字幕分段，并可以下载 SRT。被配音拉长的镜头会标出来。

试听和声音样片用的选声、去静音、响度和混音规则与正式制作完全相同，不启动任何模型，也不受推理门禁限制。建议的顺序是：改角色表 → 试听 → 生成声音样片 → 根据实际时长回头调整分镜的 `duration_sec` 或台词 → 满意后再提交制作。这样不会在 GPU 上花了时间才发现声音不对。

### 3.3 配音引擎

`voice.engine` 有两种取值。

**`say`（默认，macOS）**：中文语音需要先在 系统设置 › 辅助功能 › 朗读内容 › 系统语音 › 管理语音 里下载。没下载的语音会生成一段几乎无声的文件；开工检查和配音表会直接列出缺少的语音。

**`command`（任意配音程序）**：在 `voice.command` 里写一个参数数组，程序需要把音频写到指定文件。可用的占位符：

| 占位符 | 含义 |
|---|---|
| `{out}` | 要写出的音频文件路径（必需） |
| `{voice}` | 选声结果，即角色表 `voice`、`per_character` 或 `_male` 等槽位的值 |
| `{rate}` | 语速（每分钟字数），引擎不支持可以不用 |
| `{text}` / `{text_file}` | 台词文本 / 存放台词的 UTF-8 文件路径 |

模板里两个文本占位符都没有时，台词从标准输入传入。命令按参数数组直接执行，不经过 shell。`voice.command_ext` 是输出文件的扩展名（默认 `wav`），任何 PyAV 能解码的格式都可以。

例如本地离线的 [Piper](https://github.com/rhasspy/piper)（从标准输入读文本）：

```json
"voice": {
  "engine": "command",
  "command": ["piper", "--model", "{voice}", "--output_file", "{out}"],
  "command_ext": "wav"
}
```

此时 `{voice}` 是模型文件路径，所以要在角色表的 `voice`、`voice.per_character` 或 `cinema.voice_map` 的各个槽位里填模型路径，而不是 `say` 的语音名。

用在线服务做引擎时，台词会发送到该服务；请先确认这符合你的项目要求。以上示例没有在本次发布中实际运行，请先在页面上试听一句确认。

### 3.4 配音后处理

每句配音合成后会依次：去掉首尾静音（保留 40 毫秒）、把响度统一到目标电平、两端各做 8 毫秒淡入淡出防爆音。去掉静音之后，配音和字幕的起止时间才能对齐。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `voice.trim_silence` | `true` | 去首尾静音 |
| `voice.normalize` | `true` | 统一响度 |
| `voice.target_rms_db` | `-20` | 目标响度（dBFS） |
| `voice.peak_db` | `-1.5` | 峰值上限 |
| `voice.lead_in_sec` | `0.2` | 镜头开始到第一个字的间隔 |
| `cinema.voice_tail_sec` | `0.5` | 最后一个字到镜头结束的留白 |

### 3.5 字幕

- 超过 `subtitle.max_chars_per_line`（默认 15）字的台词，会在标点处切成几段依次显示；每段的时长按字数和标点停顿分配到这句配音的时间窗口里。
- 段尾的逗号、句号省略，问号和感叹号保留。
- 整句的第一段淡入、最后一段淡出，段与段之间直接切换。
- 烧录字幕和 `subtitles.srt` 用的是同一份分段。
- 修复：v1.0.0 转场时用的是已经烧了字幕的上一帧，上一镜的字幕会以半透明残影出现在下一镜开头。

### 3.6 音效

分镜的 `sfx` 字段可以写多个，用 `|` 分隔；一次性音效可以用 `@秒` 指定在镜头内的时间点，不写时落在镜头 35% 处。

```text
wind|sword@1.4
```

| 类型 | 名称 |
|---|---|
| 铺满整镜的环境声 | `rain` `wind` `waves` `boat` `steps` `clock` `engine` `city` `birds` `paper`，新增 `energy`（能量嗡鸣与闪光）、`fire`（火焰噼啪） |
| 一次性音效 | 新增 `impact`（冲击）、`sword`（挥剑与剑鸣）、`thunder`（雷）；原有 `door` |
| 无音效 | `silence` |

v1.0.0 的示例分镜用了 `impact`，但当时音效表里没有它，于是静默地变成了无声。现在未识别的音效名、运镜、色调和转场名都会在分镜预览里给出提示。

台词出现时，音效会自动压低到 70%（`cinema.sfx_duck_under_voice`）。

### 3.7 配乐

- `music.builtin.style: "guofeng"`：五度持续低音加五声音阶拨弦旋律。冷色调（`cool`、`noir`）用羽调式，暖色调用宫调式；色调取第一个镜头的 `grade`。`beat_sec` 控制旋律疏密，`seed` 控制旋律走向。
- 其他取值保留原来的氛围和弦垫。
- 想用自己的曲子：`music.source: "file"`，`music.file` 填音频路径。
- **闪避**：台词开始前 0.18 秒提前压低配乐，以 0.06 秒起、0.45 秒落的平滑曲线变化，降到 `duck_under_voice`（默认 0.42）。v1.0.0 只有 50 毫秒的平滑窗口，配乐会随台词忽大忽小。起落时间可用 `music.duck_attack_sec` 和 `music.duck_release_sec` 调整。

## 4. 画面

### 4.1 动态镜头的变速

镜头的实际时长由分镜时长和配音长度共同决定，经常和生成出来的片段长度不一致。v1.0.0 按帧号硬拉：预览档 17 帧（8 fps）的片段放进 3 秒镜头，每帧要重复 4 次，看起来明显卡顿。v1.1.0 的规则：

| 情况 | 处理 |
|---|---|
| 片段比镜头长 | 均匀加速，保留完整动作（与之前相同） |
| 片段比镜头短 | 放慢播放，相邻两帧之间做混合，画面连续不跳；最多放慢 `cinema.max_clip_slowdown` 倍（默认 1.5） |
| 放慢到上限仍不够长 | 停在最后一帧并缓慢推近（`cinema.hold_push_in`，默认放大 4.5%），而不是冻结 |

如果声音样片显示某个镜头被配音拉得比动作长很多，更好的做法是缩短台词、拆成两个镜头，或在分镜里调大 `duration_sec`，让生成的动作本身更长。

### 4.2 放大锐化

正式档的镜头是 480×832，交付是 1080×1920，放大约 2.3 倍。v1.1.0 在明显放大（超过 1.15 倍）时加一次轻度 USM 锐化，补回放大损失的边缘。强度由 `cinema.sharpen` 控制，默认 `0.6`，设为 `0` 关闭。锐化不会增加原生细节。

### 4.3 每镜色调与转场

- **色调**：分镜里每个镜头的 `grade`（`cool` `warm` `golden` `noir` `neutral`）现在逐镜生效。之前整集只用第一个镜头的色调。
- **转场**：新增分镜字段 `transition`，作用于该镜头开头，时长为 `cinema.transition_frames` 帧：

| 取值 | 效果 | 适合 |
|---|---|---|
| `dip`（默认） | 暗场溶解，中点压暗，避免两帧叠成“鬼影” | 大多数镜头 |
| `dissolve` | 直接溶解 | 同一场景内的柔和过渡 |
| `cut` | 硬切 | 节奏快的连续动作 |
| `flash` | 白闪 | 冲击、爆发、法术命中 |

整集默认转场可以用 `cinema.transition` 修改。

### 4.4 角色一致性

已知的失败是动态镜头里人物、服装、姿态或画风漂移。v1.1.0 加了两道约束：

1. **动作提示词带角色外观**。之前送给 Wan 和 Animate2 的动作提示词只有动作描述，角色长相、服装和道具全靠首帧维持。现在会把与关键帧相同的角色 `anchor` 一并写进去，并要求全程保持首帧的五官、发型、服装、配色与道具。所以 `anchor` 要写具体：发型、主色、服装款式、标志性配饰和手持道具。
2. **视频复检对照关键帧**。之前视频复检只看首、中、尾 3 帧，没有参照物。现在会把已通过质检的关键帧作为“角色外观基准”放在最前面，并均匀抽取 5 帧（`quality.vision.video_frames`）逐帧比对；中途换脸、换装、道具消失或画风突变判为不通过。

第 2 条会让复检更严格，重试可能变多；每次请求也会多送几张图，视觉模型的上下文要够用。不需要时可以把 `quality.vision.video_reference` 设为 `false`、把 `video_frames` 调回 `3`。这两条都还没有在真实模型上验证过。

### 4.5 在页面上检查画面

任务卡片的镜头表里，每个已生成关键帧的镜头会显示缩略图。点开后并排显示：

- 关键帧
- Wan 动作草稿（启用 Animate2 时）
- 进入成片的动态镜头（Animate2 角色迁移结果，或未启用时的 Wan 结果）

下面附该镜头的质检意见。对照这三者，可以判断漂移是出在动作草稿还是角色迁移，再决定改 `anchor`、改 `video_prompt` 还是加 `end_frame`。

## 5. 推荐流程

1. 写分镜：角色表写清楚 `anchor`、`gender`、`voice`；每个镜头写 `description`、`video_prompt`、`grade`、`sfx`，打斗镜头考虑 `transition: flash`。
2. 在制作页面导入，看分镜预览里的提示，修掉未识别的名称。
3. 看配音表，逐个角色试听，调整 `voice` 和 `voice_rate`。
4. 生成整集声音样片，检查镜头实际时长、字幕分段和混音；需要的话回到第 1 步调整台词或时长。
5. 用「动态预览」预设提交，跑通整条链路。
6. 在任务卡片里逐镜查看关键帧、动作草稿和角色迁移结果，对照质检意见修改分镜。
7. 用「正式出片」预设提交，完成后完整看一遍成片再交付。

## 6. 新配置项速查

旧配置里没有这些键时，按“默认”一列的值运行。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `voice.engine` | `say` | `say` 或 `command` |
| `voice.command` | `[]` | `command` 引擎的参数数组 |
| `voice.command_ext` | `wav` | `command` 引擎输出的扩展名 |
| `voice.trim_silence` / `normalize` | `true` / `true` | 见 3.4 |
| `voice.target_rms_db` / `peak_db` | `-20` / `-1.5` | 见 3.4 |
| `cinema.voice_map._female` / `_child` | Tingting / Flo | 新增的性别槽位（旧配置没有时也按此默认） |
| `cinema.transition` | `dip` | 整集默认转场 |
| `cinema.sharpen` | `0.6` | 放大锐化强度，`0` 关闭 |
| `cinema.max_clip_slowdown` | `1.5` | 动态镜头最多放慢几倍 |
| `cinema.hold_push_in` | `0.045` | 片段播完后的缓推幅度 |
| `cinema.sfx_duck_under_voice` | `0.7` | 台词时音效压低到的比例 |
| `music.builtin.style` | 旧配置为原值，新配置为 `guofeng` | 内置配乐风格 |
| `music.duck_attack_sec` / `duck_release_sec` | `0.06` / `0.45` | 配乐闪避起落时间 |
| `quality.vision.video_frames` | `5` | 视频复检抽帧数 |
| `quality.vision.video_reference` | `true` | 视频复检是否附关键帧参照 |

分镜新增字段：每个镜头的 `transition`；角色表的 `voice`、`voice_rate`、`gender`。

## 7. 排错

| 现象 | 处理 |
|---|---|
| 开工检查提示“系统没有安装这些语音” | 按 3.3 下载语音，或在角色表 `voice` 换成已安装的语音 |
| 配音表里所有角色都是同一个声音 | 给角色加 `gender` 或 `voice`；看“来源”一列是不是都落到了“默认音色” |
| 试听按钮是灰的 | 配音引擎不可用，鼠标悬停可以看到原因 |
| 试听有声音但音色不对 | 看“来源”一列是哪一级决定的，在更高一级里指定 |
| 声音样片里某个镜头时长远超分镜 | 台词太长；缩短台词或拆镜头，见 4.1 |
| 字幕切段位置不理想 | 在台词里调整标点，切段只发生在标点处；或调大 `subtitle.max_chars_per_line` |
| 分镜预览提示“未识别的音效” | 对照 3.6 的名称表；未识别的会静音 |
| 视频复检突然频繁不通过 | 展开质检意见；确实是误判时可以关闭 `video_reference` 或减少 `video_frames` |
| `command` 引擎报“没有写出音频文件” | 确认模板里有 `{out}`，且程序确实写到了这个路径 |

## 8. 已知限制

- 完整动态出片仍未通过验收。
- 动作提示词带外观、视频复检对照关键帧，这两项都还没有在真实模型上验证。
- 没有口型同步。
- `command` 引擎不能列出可用语音，配音表的“语音”一列显示为“—”。
- 内置国风配乐是程序合成的，适合做底；正式作品建议用 `music.source: "file"` 换成真实配乐。
- 试听和声音样片的缓存放在 `output/drama_preview/`，最多保留最近 80 个，自动清理旧的。
